# Phase 10 — Portfolio, School Reporting and Pilot Analytics

**Status:** acceptance and docs implemented on `phase10-portfolio-acceptance-docs` against `docs/product/phase-10-contract.md` and the binding `docs/decisions/ADR-008-portfolio-export-and-pilot-analytics.md`. Phase 10 is the last roadmap phase and adds no curriculum content, no new chapter and no new activity kind; it turns work the portal already holds into a student portfolio export, a narrower coordinator summary, and an admin-only pilot analytics view. This note covers the acceptance-docs agent's files only: the live acceptance suites and these docs. The export itself (`lib/portfolio-export.mjs`, `app.js`, `index.html`, `styles.css`), the coordinator summary control and `admin/analytics` (`admin.js`, `admin.css`, `functions/api/[[path]].js`, `lib/pilot-analytics.mjs`) belong to the parallel student-ui and workspace-api agents against the same contract. Preview and Production acceptance follow integration of all three agents; Production stays deferred (ADR-007).

## What Phase 10 is

Every phase so far kept student work inside the portal. Phase 10 produces two artefacts that leave the system — the student's own portfolio export and a narrower coordinator summary — and one that looks across learners for the first time, the pilot analytics view. ADR-008 governs what may and may not appear in each, and is binding wherever this note or the contract could be read to disagree with it.

- **Student portfolio export.** A single self-contained HTML file the learner produces from the existing Portfolio view at any time, with no staff involvement: display name, programme name, export date, overall completion, and per chapter the badge, the assessment level (labelled as teacher or suggested), every reflection in full, every activity evidence item, and any project deliverables and final recommendation. It never carries an email address, auth user id, `reviewed_by`, login or last-seen timestamps, IP address, or device/browser information, and it carries a standing note that this is formative pilot evidence from a keyword-based scorer with teacher override, not a certified qualification.
- **Coordinator summary.** A separate, deliberately narrower export from a different control on the same view: display name, programme name, date, chapters completed, badges earned, assessment levels and overall completion. No free-text student writing at all — no reflections, no activity evidence, no project text.
- **Pilot analytics.** A new admin-only view at `/admin` answering the roadmap's six questions — completion, resubmission/improvement, chapter drop-off, system-vs-teacher agreement, Experience Lab completion, and qualitative feedback — as aggregates only, with any cell counting fewer than five learners suppressed server-side rather than rendered as blank or zero. The existing per-learner admin review view is unchanged and is not analytics.

## Acceptance suites extended

- `tests/acceptance/lib.mjs`: a shared `noIdentifiers(text, ids)` helper (ADR-008 §1-4) asserting a body carries none of the given learner ids/display names, no `reviewed_by`, and no acceptance test-user email, reused by the API and browser suites below.
- `tests/acceptance/cutover-acceptance.mjs`: `admin/analytics` refuses a student token exactly as every other admin route does (403), an admin gets aggregates (200), and the response body — checked after a project review has already set a real `reviewed_by` value elsewhere in the system — carries no learner id, display name or `reviewed_by`.
- `tests/acceptance/ui-acceptance.mjs`: a fresh student with a marker reflection drives `#exportPortfolio` and `#exportCoordinatorSummary` from the Portfolio view and captures each download; the student export is asserted to contain `.portfolio-export`, the learner's own reflection and the `.export-note` formative-evidence wording, and to name no email, auth id or `reviewed_by`; the coordinator summary is asserted to contain no reflection text and no forbidden identifier. The admin `/admin` checks are extended: a student sees no `#adminAnalytics`; an admin sees all six `[data-measure]` values, at least one `[data-suppressed]` cell in this small pilot, and no learner id or display name anywhere in the analytics view's text.
- `tests/acceptance/ui-audit.mjs`: screenshots the admin pilot analytics view and, for the student export, opens the downloaded HTML file directly and screenshots it as a learner would see it printed, at both phone and desktop widths.
