## Design Specificity Verdict

**The instruments are authored; the container is stock.**

Authored: the session box triad (colour is the pedagogy); the Experience Lab DO/TEST/MAKE/BREAK/IMPROVE/PROVE spine; the bespoke labs (bias simulator, decision lab's evidence-citation gate, sentence annotator, dataset audit); `activityBlocker()`'s residual rule rejecting "none" in a risk register.

Stock: the home view is a marketing landing page shown to an already-committed learner every session. The chapter view (250px sticky rail + content pane) is the LMS pattern `operating-model.md` names as an anti-pattern. The type identity does not exist — `styles.css:1` declares Inter with **no `@font-face` and no stylesheet link**; every learner gets a system fallback.

**Deterministic scan:** file scan exit 2 — 19 findings (16 blocking, 3 advisory), all `line: 0`. Live URL scan: **31 blocking at 1280x800, 30 at 390x844**. URL-only: eight pixel-stack contrast findings on locked cards at **1.2:1-1.7:1**; white-on-`#e77722` 2.97:1; white-on-`#159487`. 1280 only: `line-length` ~88 chars. 390 only: two `body-text-viewport-edge` (152-char and 96-char `<p>` at 15px margin).

**Detector corrected the review:** keyboard traversal measured **0 of 25 tab stops without a visible ring** (Chromium UA default). The real finding is narrower: exactly **one** authored `:focus-visible` rule in `styles.css`, scoped to `.decision-lab`; the app inherits browser defaults never designed against eight saturated card fills. Also not broken: **zero console errors**, **zero horizontal scroll at 390px**.

**False positives dropped:** `dark-glow` on `#1f2d44` (navy elevation shadow, not a halo); `design-system-color` + `low-contrast 3.6:1` on `rgb(66,133,244)` (Google brand mark, WCAG logo exception).

**Visual overlays:** none. `impeccable live-server` serves the detector bundle, not project files (`GET /index.html` -> 404); both agents used Vite. Screenshots are the visual evidence; no live overlay exists.

## Overall Impression

The pedagogy is better than the interface by a wide margin. The evidence gates refuse completion theatre in ways most edtech never attempts — then that work is wrapped in a shell that loses the learner's highest-stakes writing on an ordinary click, cannot tell them whether anything saved, and has no URL.

Biggest opportunity: the portfolio. `chapterEvidenceItems()` already assembles fully-labelled evidence, but only for the downloaded export. The screen named "Your evidence" calls a thinner function and renders reflections only.

## What's Working

1. **The three-box triad, applied without exception across ~60 sessions.** Redundantly coded (hue + 4px rule + eyebrow text), so it survives colour-blindness and a bad panel; never borrowed for decoration.
2. **Evidence gates encoding subject-matter judgement.** `decision` requires >=3 runs with distinct starting choices, each future bound to a different run; `dataset` requires >=5 findings across >=3 issue types; `simulator` requires two runs that differ in a parameter.
3. **Safety framing written for a real 15-year-old.** Privacy rules on an amber left rule before the link, in plain imperatives, with `.lab-fallback` as a first-class offline route.

## Priority Issues

### [P0] The learner's work is destroyed by ordinary use, in two places
`capstoneHTML()` renders `<textarea data-capstone="${i}">` with no value from state and no `oninput`; `renderChapterCapstone()` runs at the end of every `renderLesson()`. Any session-rail click wipes typed capstone answers — the gate to the next chapter, and the only text in the product that is not persisted. Separately `wireActivity()`'s `if(s.activity.kind==='testlog')renderLesson()` re-renders on every change; measured focus drop to `BODY`, ~40 times per log.
**Fix:** route capstone drafts through `state.chapterAssessments[blockId].draft`, populate `value`, add `oninput` -> `scheduleSync()`. Replace the testlog `renderLesson()` with a targeted cell update.
**Command:** `/impeccable harden`

### [P0] The Experience Lab safety gate is CSS-only and keyboard-bypassable
`#labToolLink` is a live `<a href>` gated by `pointer-events:none` + `aria-disabled="true"`. Measured `tabIndex 0` with live `href`: Tab + Enter opens the third-party tool with the privacy notice unread and `ack` false. The product's only recorded consent that a minor read the safeguarding notice. What needs gating is the exposure, not the completion.
**Fix:** render as `<button disabled>`, swap for a real `<a>` only once `ack` is true. Enlarge the ack checkbox — **13x13px** against WCAG 2.2 SC 2.5.8's 24px floor.
**Command:** `/impeccable harden`

### [P1] Nothing is announced, nothing takes focus, no routes
Zero `aria-live`/`role="alert"`/`role="status"` nodes — every `feedback()` message is silent. `show()` never scrolls or moves focus (measured: `scrollY 1400` -> `533`, `activeElement === BODY`). At 390px `#authBtn`'s accessible name is literally `"G"`. WCAG 2.2 AA is binding per PRODUCT.md; no routing also blocks coordinator deep-links and makes reload/Back dump the learner to the hero.
**Fix:** `role="status"` on `.result`, `role="alert"` on blocking variants; `show()` scrolls to top and focuses the view's `<h1>` (`tabindex="-1"`); `aria-label` on `#authBtn`; a `hashchange` route (`#/b2/b2s3`).
**Command:** `/impeccable harden`

### [P1] Locked cards hide the instruction the learner needs; unlocked cards fail AA too
`.block-card.locked{filter:saturate(.5);opacity:.58}` dims container and text; pixel-sampled **1.2:1-1.7:1** across 7 instances, worse than the prior audit's 1.48:1 estimate because `.block-card p{opacity:.95}` compounds to ~0.55. The same opacity drags unlocked cards: Ch2 description **2.83:1**, Ch1 — the current chapter — **3.53:1**. The locked card is `disabled`, so the click is silently dead.
**Fix:** desaturated surface with full-contrast ink and a 3px left rule in the chapter hue; drop `opacity` from `.block-card p` and `.card-top`, darken the two failing hues; make locked cards focusable and scroll to the blocking capstone on activation.
**Command:** `/impeccable colorize`

### [P1] "Your evidence" shows almost no evidence
`renderPortfolio()` renders mission + `My reflection:` per completed session and nothing else. Verified live: four rows reading `My reflection:` followed by empty space, then seven near-identical empty cards. `chapterEvidenceItems()` already assembles the real evidence — for the export only. This is where the 30-hour peak-end curve currently lands.
**Fix:** call `chapterEvidenceItems()` on screen; collapse unstarted chapters to one line; suppress empty reflection rows.
**Command:** `/impeccable layout`

## Minor Observations

- `renderHome()`'s `classList.toggle('google-btn', !signed)` leaves `#authBtn` classless when signed in; two different sign-out treatments from one state change.
- `.lab-stage` is `<b>DO</b><span>Draw for the AI</span>` with no separator — read aloud as `"DODraw for the AI"`.
- `esc()` at `app.js:19` maps `"` to `&quot` — missing semicolon. Harmless where used; real bug in the escaping primitive.
- `.block-card.done` is set in `renderHome()` but has no rule in `styles.css`.
- The Experience Lab and `assessment.css` use `rgba(0,0,0,.12)` / `rgba(255,255,255,.72)` and 14px radii instead of the system's line colours and scale.
- `.route-card` "textbook timing" and hard-coded chapter durations conflict with PRODUCT.md's withdrawn-scheduling decision.
- `#hintBtn` styled `.secondary` over-promises for a control returning a constant.
- Detector's `wide-tracking` on `letter-spacing:0.11em` is the eyebrow label DESIGN.md establishes — accepted deviation.
